# Данные: как мы готовили датасет

Организаторы дали 12 064 снимка МРТ в четырех классах: глиома, менингиома, опухоль гипофиза, опухоли нет. Использовать набор как есть было нельзя: почти три четверти тестовых снимков — копии обучающих, разных снимков втрое меньше, чем файлов, а обводок опухолей нет вовсе. Здесь описано, что мы нашли и как это исправили. Код каждого шага — в `src/`, порядок команд — в README, раздел «Как фильтровали исходный датасет».

| | Было | Стало |
| --- | --- | --- |
| Файлов | 12 064 | 3982 уникальных снимка |
| Тестовых снимков с копией в обучающей части | 72,9% | 0 |
| Пациентов сразу в обучающей и тестовой частях | 166 из 206 | 0 |
| Снимков опухолей с обводкой | 0 | 3064 |
| Снимков в двух классах сразу | 6 | 0 |
| Снимков КТ и спорных в классе «опухоли нет» | 115 из 466 | 0 |

## 1. Исходные данные

| Класс | Обучающая часть организаторов | Тестовая часть организаторов |
| --- | --- | --- |
| Глиома | 3018 | 755 |
| Менингиома | 2183 | 546 |
| Опухоль гипофиза | 2504 | 626 |
| Опухоли нет | 1945 | 487 |
| Всего | 9650 | 2414 |

Имена файлов устроены по шести разным схемам — набор собран из нескольких источников. Обучающая и тестовая части собраны из разных смесей: 60% теста — файлы с числовыми именами, в обучающей части таких 5%. Рядом с оригиналами лежат искаженные копии с суффиксами в имени: `BR` — осветление почти вдвое, `DA` — затемнение, `HF` и `VF` — отражения, `RO` — поворот, `SP` — точечный шум. Все копии сжаты до 224×224.

Код: `src/build_index.py`, отчет — `reports/index_report.md`.

## 2. Копии и утечка

Модель учат на одних снимках, а проверяют на других. Если снимки из проверки уже были в обучении, оценка получается завышенной — это утечка.

Мы сравнили все файлы по содержимому, а не по имени: для каждого снимка посчитали «отпечаток» (perceptual hash), который не меняется при пересохранении, отражении, повороте и изменении яркости, и перепроверили найденные пары сравнением уменьшенных копий. 30 случайных пар просмотрели глазами — все оказались одним и тем же снимком.

| Проверка | Результат |
| --- | --- |
| Тестовых файлов с точной копией в обучающей части | 1761 из 2414 (72,9%) |
| То же по классам | гипофиз 94%, опухоли нет 88%, глиома 64%, менингиома 48% |
| Файлов, у которых есть хотя бы одна копия | 9309 из 12 064 |
| Уникальных снимков, лежащих сразу в обеих частях | 1253 |
| Пациентов в обеих частях (когда стали известны пациенты) | 166 из 206 |

Решение: исходное деление организаторов не используем, все оригиналы делим заново — по пациентам (раздел 6). Цену утечки мы измерили на готовой модели: на тесте организаторов класс верен у 86,4% снимков знакомых пациентов и у 75,7% новых.

Код: `src/find_duplicates.py`, `src/imhash.py`; отчет — `reports/leakage_report.md`.

## 3. Обводки и пациенты из Figshare

Снимки опухолей в кейсе оказались взяты из открытого набора Figshare (Cheng et al., лицензия CC BY 4.0): 3064 среза МРТ T1 с контрастом с ручными обводками опухолей и номерами пациентов. Мы скачали его и тем же «отпечатком» нашли двойника для каждого снимка кейса.

| Класс | Оригиналов кейса найдено в Figshare |
| --- | --- |
| Глиома | 89,4% |
| Опухоль гипофиза | 83,4% |
| Менингиома | 73,1% |
| Опухоли нет | 0% |

- Сопоставление вернуло обводки для 82% уникальных снимков опухолей и номер пациента для 68% оригиналов кейса.
- 20 случайных пар проверили глазами: обводка из Figshare ложится на опухоль снимка кейса.
- Пациентов в Figshare 209, а не 233, как указано авторами: у 42 номеров одна основа и разная буква на конце — это повторные исследования одних людей, мы считаем их одним пациентом.
- Половина снимков кейса зеркальна относительно Figshare, поэтому сторону поражения система не сообщает.
- Опухоль занимает малую часть кадра: обычно 0,7% у гипофиза и 1,8% у глиомы.

Код: `src/download_figshare.py`, `src/convert_figshare.py`, `src/match_figshare.py`; отчеты — `reports/figshare_match_report.md`, `reports/masks_report.md`.

## 4. Исправление меток

Шесть снимков (51 файл с копиями) лежали сразу в двух классах. Мы сверили метки кейса с Figshare, где метку ставили вместе с обводкой: 42 файла перемаркированы из «гипофиза» в «менингиому». Один спорный случай (глиома или менингиома, 10 файлов) в Figshare не нашелся и исключен. Файлы организаторов не менялись: правки записаны в таблицу `data/processed/label_fixes.csv` и применяются при сборке данных.

Код: `src/make_label_fixes.py`.

## 5. Проверка класса «опухоли нет»

Мы просмотрели все 466 уникальных снимков класса: под каждым отмечали режим съемки (T1 с контрастом, T1, T2, FLAIR, КТ) и находки (норма, опухоль, другое). 160 снимков независимо размечены дважды. Отметки считывались с листов программой, считывание проверено по 160 клеткам.

| Что нашли | Снимков из 466 |
| --- | --- |
| Компьютерная томография, а не МРТ | 33 |
| «Опухоль» отмечена хотя бы одним проверяющим | 91 |
| Другая болезнь | 119 |
| Режим определить нельзя | 20 |
| Снят в T1 с контрастом, как опухоли | 21 |
| То же и при этом «норма» | 10–12 |

Правило отбора записали до обучения: снимок остается, если никто не отметил КТ, никто не отметил опухоль и снимок читаем; при расхождении проверяющих достаточно одной отметки, чтобы исключить снимок. Исключено 115 снимков, осталось 351: 278 «норма» и 73 с другой болезнью без опухоли. Вторые оставлены намеренно: система должна отличать опухоль от других изменений.

Код: `src/read_doctor_marks.py`, `src/merge_doctor_marks.py`, `src/make_review_decisions.py`; отметки — `reports/doctor/no_tumor_review/`, решения — `data/processed/review_decisions.csv`, отчет — `reports/doctor_marks_report.md`.

## 6. Деление по пациентам

Срезы одного человека похожи друг на друга, поэтому делили не снимки, а группы: в группу входят копии снимка, тот же срез в другом кадрировании и все снимки одного пациента. Деление — `StratifiedGroupKFold` на 7 частей с seed 42: часть 1 — тест, часть 3 — проверочная, остальное — обучение. Деление заморожено (`data/processed/folds_frozen.csv`): исключения из раздела 5 применены после него и ни один снимок не сменил часть. Все проверки пересечения между частями дают ноль.

Код: `src/make_splits.py`; судьба каждого из 12 064 файлов — `data/processed/splits.csv`, отчет — `reports/splits_report.md`.

## 9. Аугментации

Готовые копии организаторов в обучении не используем: среди них есть перевернутые вверх ногами снимки, чего в жизни не бывает. Аугментации делаем сами, на лету: отражение по горизонтали, поворот до 15°, сдвиг и масштаб, яркость и контраст, шум, размытие. Против «обходного пути» (раздел 10) добавлены искажения «под другой аппарат»: ухудшение разрешения, сжатие JPEG, резкость, гамма, меньше уровней серого.

Код: `src/dataset.py`, настройки — `configs/base.yaml`; примеры — `reports/dataset_report.md`.

## 10. «Обходной путь»

Мы проверили, можно ли угадать класс, не глядя на мозг, — только по техническим свойствам файла. Мера — AUC: 0,5 — угадать нельзя, 1,0 — угадывается всегда.

| Что видит простая модель | AUC «опухоль есть / нет» |
| --- | --- |
| Только размер файла | 0,979 |
| Все технические свойства файла | 0,986 |
| Свойства снимка после единой подготовки | 0,898 |
| То же с аугментациями «под другой аппарат» | 0,69 |

Причина — в составе данных: размер 512×512 у 85–96% снимков опухолей и у 1,1% снимков без опухоли, снимки без опухоли резче и сжаты слабее, и все они не из Figshare. Чистка класса этого не изменила (AUC по размеру файла 0,982). Единая подготовка и аугментации перекос ослабляют, но не убирают; поэтому мы проверяем модели стресс-тестом и тестом с закрашиванием опухоли (`docs/models.md`).

Код: `src/check_shortcut.py`; отчет — `reports/shortcut_report.md`.

## Что не исправлено

- **Здоровых снимков в том же режиме, что опухоли, почти нет.** Опухоли сняты в T1 с контрастом, а из 351 снимка без опухоли в этом режиме около десяти. Модель может отличать режим и источник, а не отсутствие опухоли. Поэтому показатели «нет опухоли» мы приводим отдельно по режиму T1.
- **Снимков без опухоли мало:** 351, в тесте 49. Одна ошибка на тесте меняет показатель на 2 процентных пункта.
- **Большую часть снимков без опухоли смотрел один человек** (241 из 351); там, где смотрели двое, они часто расходились.
- **«Опухоли нет» не значит «здоров»:** 73 снимка — с другими болезнями.
- **У 567 снимков опухолей нет обводки** — их нет в Figshare.
- **Пациент неизвестен** для снимков без опухоли и примерно для 18% снимков опухолей: срезы одного человека там могли попасть в разные части.
