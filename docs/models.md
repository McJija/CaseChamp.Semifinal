# Модели: что выбрали, что пробовали и почему

## Коротко

- **Две модели проверяют друг друга.** Классификатор (ResNet34) называет тип опухоли, сегментатор (U-Net на том же ResNet34) обводит ее по пикселям.
- **«Опухоль есть», если** сегментатор обвел область больше 50 пикселей **или** классификатор уверен в опухоли не меньше чем на 0,976. Тип — самый вероятный из трех у классификатора. Если модели не согласны, система ставит флаг «требует внимания врача».
- **Легкие модели:** снимок обрабатывается за 0,6 с на обычном процессоре, видеокарта не нужна. Обе модели обучены в бесплатном Kaggle на видеокарте T4: классификатор — около 3,5 минуты, сегментатор — около 14.
- **Результат на тесте** (582 снимка новых пациентов): найдено 528 из 533 опухолей, верно «нет опухоли» 48 из 49, тип верен у 443 из 528 найденных, Dice обводки 0,75. Подробно — `reports/metrics.md`.

## Что определило выбор

| Ограничение | Что из него следует |
| --- | --- |
| 2875 снимков в обучении | Обучать с нуля нельзя — берем сети, предобученные на ImageNet |
| Обводки есть только у срезов с опухолью (3064 среза Figshare) | Классификатор учится на всех снимках, сегментатор — на снимках с обводкой |
| Класс «нет опухоли» угадывается по формату файла (AUC 0,979) | Решение должно опираться на опухоль; нужны проверки против «обходного пути» |
| Работа в больнице без видеокарты | Легкие модели, доли секунды на снимок |
| Обучение только в бесплатном Kaggle | Стандартные, предсказуемые архитектуры, немного запусков |

## Схема

```
снимок → подготовка 256×256 ─┬→ классификатор → тип, вероятности, тепловая карта ─┐
                             └→ сегментатор   → обводка, площадь ─────────────────┴→ правило «опухоль есть» и флаг → врачу
```

Почему две отдельные модели, а не одна общая:

- **Сегментация сама по себе не защищает от «обходного пути».** Обводки есть только у снимков с опухолью, поэтому на вопросе «опухоль есть или нет» общая сеть не получает от сегментации дополнительного сигнала.
- **Независимые модели ошибаются по-разному.** Их расхождение — осмысленный повод позвать врача. У сети с общим кодировщиком ошибки двух выходов связаны.
- **Проще проверять и заменять.** Каждую модель можно обучить, оценить и заменить отдельно.

## Классификатор

- **Архитектура:** ResNet34 из библиотеки timm, выход на четыре класса.
- **Данные:** все 2875 снимков обучающей части.
- **Вход:** серый снимок 256×256 после единой подготовки (`docs/data.md`, раздел 8).
- **Потери:** перекрестная энтропия с весами классов (глиома 0,63, менингиома 1,04, гипофиз 0,91, нет опухоли 2,92): снимков без опухоли вчетверо меньше.
- **Аугментации:** базовые и искажения «под другой аппарат» (`docs/data.md`, раздел 9).
- **Выбор эпохи:** лучший macro-F1 по четырем классам на проверочной части среди эпох с чувствительностью к опухоли не ниже 0,95. Одна чувствительность не годится: сеть, которая всегда отвечает «опухоль», дает чувствительность 1.

## Сегментатор

- **Архитектура:** U-Net из segmentation_models_pytorch с тем же кодировщиком ResNet34. U-Net — стандарт медицинской сегментации: сквозные связи сохраняют мелкие детали, и сеть хорошо учится на небольших наборах.
- **Данные:** 2229 срезов Figshare с обводками и 246 снимков без опухоли с пустой обводкой.
- **Потери:** Dice + BCE. Опухоль занимает около 1% кадра: Dice не дает сети выучить «везде фон», BCE делает обучение устойчивым.
- **Выбор эпохи:** по Dice на проверочной части.

Снимки без опухоли мы добавили не сразу. Без них сегментатор рисовал ложные обводки на 40–43 из 56 снимков без опухоли: он никогда не видел снимков другого вида. Две другие попытки это не исправили (таблица ниже). С пустыми обводками ложных обводок стало 0–1 из 56, а точность обводки не упала.

## Правило «опухоль есть» и флаг

Решение принимают обе модели. Порог для классификатора подобран только на проверочной части — по правилу, записанному заранее: наибольшая доля верных «нет опухоли» при чувствительности не ниже 0,985. Получилось 0,976 (`configs/presence.yaml`, код — `src/presence.py`).

Так мы компенсируем слабость классификатора (раздел «Проверки»): сегментатор учится по пикселям опухоли, и на тесте две модели вместе находят на 10 опухолей больше, чем один классификатор, — особенно на снимках из других источников (58 из 59 против 51).

Флаг «требует внимания врача» ставится, когда классификатор и сегментатор отвечают по-разному. На тесте ответ системы среди снимков с флагом неверен в 40% случаев, без флага — в 14%: флаг указывает туда, где ошибка втрое вероятнее.

## Кодировщик

Замер на ноутбуке (Ryzen 5 5600H, без видеокарты), один снимок 256×256, медиана 40 прогонов (`src/bench_models.py`, `reports/model_bench.csv`):

| Кодировщик | Классификатор: млн параметров / мс | U-Net: млн параметров / мс |
| --- | --- | --- |
| ResNet18 | 11,2 / 50 | 14,3 / 105 |
| **ResNet34** | **21,3 / 95** | **24,4 / 146** |
| EfficientNet-B0 | 4,0 / 47 | 5,8 / 113 |
| EfficientNet-B3 | 10,7 / 84 | 12,6 / 137 |
| ConvNeXt-Tiny | 27,8 / 120 | 31,9 / 180 |

Выбрали ResNet34 для обеих моделей: это самый отработанный кодировщик для U-Net на небольших медицинских наборах, он устойчиво дообучается и дает чистые тепловые карты. Один кодировщик у обеих моделей упрощает сравнение. Более легкий EfficientNet-B0 мы собирались проверить отдельным запуском, но не успели к сроку.

## Дообучение

| Фаза | Что учится | Скорость обучения |
| --- | --- | --- |
| 1 | Только выход: у классификатора — последний слой, у сегментатора — декодер; кодировщик заморожен | 3·10⁻⁴ |
| 2 | Вся сеть | выход 3·10⁻⁴, кодировщик в 10 раз ниже |

- Классификатор — 20 эпох, из них 1 в первой фазе; сегментатор — 40 эпох, из них 5 в первой фазе.
- AdamW, косинусное расписание, батч 32, смешанная точность на видеокарте; оценка на проверочной части — в обычной точности, чтобы числа совпадали при пересчете на процессоре.
- В начале обучения выходы сети случайны и дают большие ошибки. Если сразу учить всю сеть, эти ошибки портят предобученный кодировщик. После первой фазы выходы уже осмысленны, и кодировщик подстраивается под МРТ бережно.

## Как мы сравнивали варианты

- **Правило замены записывали до запуска.** Новый вариант принимаем, только если он выигрывает по заранее выбранной мере и не теряет больше заданного в чувствительности.
- **Каждое решающее сравнение — на трех seed обучения** (42, 43, 44); в отчет идут среднее и разброс. Деление данных всегда одно.
- **Сравниваем только на проверочной части.** Тест открыли один раз, после заморозки моделей.

Все 27 обучений — в `reports/experiments.csv`, всего около 3 часов видеокарты. Итог на проверочной части:

| Вариант | Что менялось | Результат | Решение |
| --- | --- | --- | --- |
| `run1_cls` | классификатор с искажениями «под другой аппарат» | macro-F1 0,933, чувствительность 0,987 | **принят (seed 42)** |
| `run1_cls_nodr` | без этих искажений | по метрикам так же, на стресс-тесте хуже: 1,6% сменившихся ответов против 0,1% | не принят |
| `run1_cls_cf` | обучение со снимками, где опухоль закрашена | зависимость ответа от опухоли 17%, чувствительность −1,07 п.п. | не принят по правилу |
| `run1_cls_cf40` | то же, 40 эпох | зависимость 60%, чувствительность −1,78 п.п. | не принят по правилу |

## Проверки против «обходного пути»

- **Стресс-тест.** Снимки опухолей приводим к техническому профилю снимков без опухоли (размер, резкость, сжатие), а снимки без опухоли — наоборот, и смотрим, сколько ответов изменилось. На тесте — 0,6%: по формату файла система почти не решает.
- **Закрашивание опухоли.** Опухоль закрашиваем по обводке и смотрим, изменится ли ответ; для контроля закрашиваем такой же участок вне опухоли. Классификатор не изменил ответ «опухоль» ни на одном из 391 снимка проверочной части. Значит, он узнает вид снимка «T1 с контрастом из этого источника», а не саму опухоль. Причина — в составе данных: здоровых снимков T1 с контрастом в наборе 10–12, и вид снимка всегда подсказывает ответ. Больше снимков того же состава не помогут. Обучение с закрашенной опухолью сделало ответ зависимым от опухоли (до 60%), но стоило чувствительности и по правилу не прошло. Поэтому решение «опухоль есть» мы принимаем по двум моделям.
- **Результаты по источникам и режимам.** Чувствительность считаем отдельно для срезов Figshare и снимков из других источников, верные «нет опухоли» — отдельно для режима T1 (`reports/metrics.md`).

Определения проверок записаны до первого обучения: `configs/eval_definitions.yaml`, преобразования — `src/stress.py`.

## Пояснения для врача

- **Обводка** поверх снимка — где система видит опухоль.
- **Тепловая карта Grad-CAM** — на какую область опирался классификатор. Ее разрешение 8×8 ячеек: она показывает область, а не контур.
- **Вероятности всех типов.** Высокой уверенности можно верить: при уверенности от 0,97 тип неверен у 2 из 196 найденных опухолей на тесте. В середине шкалы уверенность завышена, калибровку мы не делали.
- **Флаг** — модели не согласны.

## Рассмотренные подходы

| Подход | Решение | Почему |
| --- | --- | --- |
| Классификатор + сегментатор | **основная схема** | Независимые модели, перекрестная проверка, простая отладка |
| Одна сеть с двумя выходами (U-Net с классификационной головой) | не запускалась — не успели к сроку | Обводки есть только у опухолей: от «обходного пути» на вопросе «есть или нет» это не защищает |
| Тип по вырезанной области опухоли | идея | Убирает фон, но теряет расположение опухоли — важный признак типа |
| Классификатор + MedSAM по тепловой карте | только для предразметки | Обводка зависела бы от тепловой карты, а классификатор смотрит не на опухоль |
| nnU-Net v2 как эталон сегментации | не успели | Сильный эталон, но долгое обучение и тяжелый вывод |
| Рамки: YOLO, Faster R-CNN | отклонены | Рамка грубее обводки; у Ultralytics YOLO лицензия AGPL |
| 2.5D и 3D | отклонены | В данных отдельные срезы без порядка и без объема |
| Трансформеры (ViT, Swin, SegFormer) | отклонены | Мало данных; легкая сверточная сеть быстрее без видеокарты |
| Поиск аномалий по норме | отклонен | Здоровых снимков T1 с контрастом почти нет |
| Признаки обводки + простая модель для типа | проверено отдельно, в систему не входит | 10 признаков (яркость, четкость края, положение) различают типы в 88% на проверочной части; на 7 ошибках классификатора правы в 5 — `reports/location_report.md` |

Способы дообучения: только выход при замороженном кодировщике — мало, признаки ImageNet далеки от МРТ; вся сеть сразу — портит предобученные веса; LoRA и адаптеры не нужны для сетей такого размера; самообучение на своих снимках требует десятков тысяч снимков. Выбрано двухфазное дообучение.

## Если бы готовых масок не нашлось

В данных кейса обводок опухолей нет. Мы не размечали их сами, потому что нашли готовые в открытом наборе Figshare, с которым совпала большая часть снимков. Без него задачу пришлось бы решать так — и так же ее придется решать при внедрении: в больнице готовых обводок не будет.

1. **Искать готовое.** Открытые наборы с обводками в T1 с контрастом — для предобучения (например, BraTS для глиом; там срезы из объемных снимков и удален череп, условия использования нужно проверить).
2. **Размечать с помощником.** Врач ставит рамку или точку на опухоли, модель-помощник (MedSAM, SAM или наш сегментатор) рисует контур, врач его правит. По оценке — 20–40 секунд на снимок вместо нескольких минут ручной обводки.
3. **Активное обучение.** Размечаются 200–300 снимков, выбранных по классам и пациентам; на них учится первый U-Net; он предразмечает остальные, врач в первую очередь правит снимки, где модель сомневается; 2–3 круга.
4. **Контроль качества.** 30–50 снимков размечают два врача; совпадение их обводок (Dice) — потолок, выше которого от модели ждать нечего.

Что не годится как основной путь: тепловые карты классификатора вместо обводок — классификатор смотрит не на опухоль, и такие «обводки» указывали бы не туда; поиск аномалий по здоровым снимкам — здоровых снимков T1 с контрастом почти нет.

## Чего модели не решают

- На здоровых снимках T1 с контрастом система почти не проверена: таких снимков в данных 10–12.
- Тип опухоли на новых пациентах верен примерно в 84% случаев (на проверочной части — 96%); ошибки собраны у нескольких пациентов.
- Обводка глиомы заметно хуже, чем менингиомы и опухоли гипофиза (Dice 0,63 против 0,88 и 0,85).
- Система работает по отдельным срезам, без объема серии.
